# Hazard Label Studio — Consistency Audit Report

> Generated by the `project-consistency-audit` workflow (4 mappers → 8 audit dimensions → adversarial verification → synthesis). 65 agents, 26 raw findings → 22 confirmed → 18 after de-dup; 4 dropped by verification. **Overall health: fair.**

## Executive Summary

After two independent skeptics re-checked every finding against the real source, **18 issues were confirmed** and **4 were dropped** (build passes cleanly; three speculative correctness/scaling claims did not survive verification).

There are **no critical or high-severity defects**. The confirmed issues fall into two recurring themes:

1. **Design-token bypass / dark-mode contrast** — a family of hardcoded color literals (`#000`, `#1a1814`, `rgba(220,38,38,.14)`, `#fff`/`#fde8e8`, `#16a34a`) authored against light-mode values that do not adapt when the dark palette inverts. The acute case is the primary Export button hover (text becomes near-invisible on a `#000` surface in dark mode).
2. **Accessibility / UX polish** — sub-minimum hit targets (3px pin edges, 18px swatches, 10px handles), an incomplete WAI-ARIA tab pattern, and an Export popover that lacks the outside-click/Escape dismissal its sibling context menu already implements.

The remaining items are dead code/exports, a React anti-pattern, and latent code-shape inconsistencies with no observable runtime effect. The single most important fix is the Export button hover; the rest are best handled as one batched token-consistency-and-a11y cleanup.

## Dark-Mode Contrast

**Primary Export button hover goes to pure black, making its label near-invisible in dark mode** (medium, `src/styles.css:360`, 2/2) — `.export-btn.primary:hover` hardcodes `background: #000` while `color` stays `var(--bg)` (`#1b1e24` in dark). On hover the live "Download SVG" button (`App.jsx:2410`) becomes near-black text on pure black (~1.2:1); the `.ext` ".svg" badge (`styles.css:366`, `color: var(--bg-2)` = `#0f1115`) is worse. **Fix:** `.export-btn.primary:hover { background: var(--accent); color: #fff; }` (matches the primary-action convention at `styles.css:381`; `--accent` is identical in both themes), and override `.ext` color on hover too.

**FormatIcon thumbnails use a hardcoded near-black ink (`#1a1814`) on theme-aware tiles, going nearly invisible in dark mode** (medium, `src/App.jsx:317`, 2/2) — `const ink = '#1a1814'` drives outlines/strokes/ticks across most format thumbnails. They render in `.format-tile` (dark bg `var(--white)` = `#232932`, or `var(--bg-2)` = `#0f1115` when selected), giving ~1.07–1.21:1 contrast. The outline-only `blank` tile goes fully empty in dark mode; banner/tag/ppe/prohibition lose their structural borders. **Fix:** drive thumbnail ink from `var(--ink)` (SVG presentation attrs accept `var()`), keeping the saturated brand accents fixed. Caveat: the ghs-label diamond uses `fill="#fff"` with `#1a1814` interior ticks — leave those internal ticks as-is or they invert.

## Token Bypass

**Ruler selection band hardcodes `rgba(220,38,38,.14)` instead of tracking the focus-ring tint** (low, `src/App.jsx:2467`, 2/2) — exact light-mode `--ring` tint; in dark mode `--ring` deepens to `.28` but the band stays `.14`. Sibling ruler elements are correctly tokenized. **Fix:** add `--ring-fill: rgba(220,38,38,.14)` (light) / `.28` (dark) and use `const band = 'var(--ring-fill)'`. Note: `--ring` is a full box-shadow value, not a color, so the band can't literally reference it.

**Selection/rotate handle base fill and hover are hardcoded light literals** (nit, `src/styles.css:479`, 2/2) — `.handle`/`.handle-rotate` use `background: #fff` and `:hover` uses `#fde8e8`, while `.handle.canvas` correctly uses `var(--bg)`. **Fix:** replace the `#fde8e8` hover (lines 494, 505) with `var(--accent-soft)`. The white base fill may be intentional contrast against artwork — keep it or document; don't blindly switch to `var(--white)` (darkens handles on dark artwork).

**Multi-select `sel-thin` / `marquee` use raw rgba reds while siblings use `var(--sel)`** (nit, `src/styles.css:924`, 2/2) — `.sel-thin` (`rgba(220,38,38,.55)`) and `.marquee` bg (`rgba(220,38,38,.08)`) are raw literals; `.group-box`, `.snap-guide`, and `.marquee`'s own border use `var(--sel)`. Zero current visual difference (no dark `--sel` override), but they won't track future accent changes. **Fix:** `color-mix(in srgb, var(--sel) 55%, transparent)` / `8%`, or add `--sel-thin`/`--sel-fill` tokens.

## Missing Dark Override

**`save-state` "saved" green (`#16a34a`) is the only semantic-success color with no token and no dark override** (nit, `src/styles.css:801`, 2/2) — sole success hue bypassing the token system; legible today (~3.2:1) but never adapts. **Fix:** add `--success: #16a34a` (optional brighter dark variant `#22c55e`) and reference it. Isolated, non-breaking.

## Accessibility / UX Polish

**Export popover has no outside-click or Escape dismissal** (medium, `src/App.jsx:2531-2532`, 2/2) — toggled only by its button; no `setExportOpen(false)` anywhere, no backdrop, no Escape effect, and it stays open after a completed export. The sibling context menu already sets the correct pattern (`.ctx-backdrop` + Escape effect). **Fix:** mirror the context-menu pattern — backdrop `onMouseDown={() => setExportOpen(false)}`, an Escape `useEffect` guarded by `if (!exportOpen) return;`, `aria-expanded` on the button, and close after a successful export.

**Right-panel tabs declare tablist/tab roles but content isn't a tabpanel and tabs lack `aria-controls`** (low, `src/App.jsx:2769-2798`, 2/2) — incomplete WAI-ARIA tab pattern (no `role="tabpanel"`/`id`/`aria-labelledby`/`aria-controls`, no roving tabindex). The left rail switchers expose only a CSS `.on` class with no `aria-pressed`. **Fix:** either complete the pattern, or simpler — drop the tab roles and use `aria-pressed`. Add `aria-pressed` to the rail buttons for consistency.

**Numeric companion field on Slider ignores `max` — accepts out-of-range values** (low, `src/App.jsx:219-226`, 2/2) — the range input clamps but the paired `<input type="number">` omits `max`, and `commit()` only rejects empty/`-`/NaN, not out-of-range. A user can type 9999 and it commits to layer state (un-representable by the slider). Affects all 13 Slider uses. **Fix:** clamp in `commit()` — `onChange(Math.min(max, Math.max(min, n)))`.

**Pin-side toggle edges are 3px hit targets and not keyboard-operable** (nit, `src/styles.css:637-640`, 2/2) — plain `<div onClick>`, but mitigated by real `<input type="checkbox">` labels for the same toggles. **Fix:** mark the diagram `aria-hidden="true"` and rely on the checkboxes, or enlarge the hit area + add `role="button"`/`tabIndex`/`onKeyDown`.

**Standard-color swatches are 18px buttons, below recommended hit-target size** (low, `src/styles.css:199-202`, 2/2) — 18×18px with a 4px gap (spacing exception doesn't apply). Mitigated by the adjacent native color input and hex field. **Fix:** `min-width/height:24px` (or a transparent ~24px padding ring around the 18px chip).

**Selection/resize handles are 10px with no keyboard resize alternative on-canvas** (low, `src/styles.css:475-505`, 2/2) — softened by its own evidence: the Properties panel exposes keyboard-accessible W/H inputs and a Rotation slider, so keyboard users *can* resize/rotate, just not from the overlay. **Fix:** optionally enlarge the pointer hit area with a transparent `::before`; treat the panel controls as the documented keyboard path.

## Interaction Wiring

**Two independent Escape handlers fire simultaneously while the context menu is open** (low, `src/App.jsx:1922`, 2/2) — one Escape both dismisses the menu *and* clears the selection. **Fix:** guard the main handler — `if (e.key === 'Escape') { if (!ctxMenu) setSelectedIds([]); return; }` and add `ctxMenu` to deps. `stopPropagation()` won't work (keydown hits `document` before `window`).

**Autosave flips to "saving" and reschedules a localStorage write on every mousemove during a drag** (low, `src/App.jsx:1137-1147`, 2/2) — per-frame timer churn; functionally correct (only the trailing write lands). **Fix needs care:** the naive `if (inDragRef.current) return;` guard is **unsafe** here — `forceCommit` reuses the same `design` ref, so the post-drag write would never fire. Debounce the `setSaveState('saving')`/timer scheduling instead, or key autosave off an explicit drag-end signal.

**Post-drag history relies solely on `setTimeout(forceCommit,0)`; no fallback if a move handler throws** (nit, `src/App.jsx:1597-1603`, 2/2) — latent: move handlers only do guarded arithmetic (NaN, not throws), so no reachable trigger. **Fix:** defensive — wrap each `move` body in `try { … } catch { up(); }`.

**Backspace with no selection isn't `preventDefault`'d** (low, `src/App.jsx:1916`, 1/2) — structurally accurate, but largely obsolete: modern Chrome/Firefox no longer map bare Backspace to history-back, so it's a harmless no-op (one skeptic dissented). **Fix:** defensive — `if (e.key === 'Backspace') e.preventDefault();` after the `if (inField) return;` guard.

## Correctness (Latent)

**Stroke severity-binding inconsistent across shape types** (low, `src/Label.jsx:260`, 1/2) — stroke routes through `resolveFill` for `line` and the rect strokeOnTop pass, but emits `l.stroke || 'none'` directly for `polygon`/`ellipse`/rect first pass. **Fully latent:** every `bindSeverity` usage is on rect/text *fill*; no code path produces a stroke-bound polygon/ellipse, so zero observable effect. **Fix:** pick one policy uniformly, or document that stroke isn't severity-bindable.

## Dead Code / Dead Exports

**`Label` receives a `selectedId` prop it never uses** (low, `src/Label.jsx:852` + `src/App.jsx:2610`, 2/2) — selection visuals are drawn by the `<Handles>` overlay, not the SVG. **Fix:** remove from the Label destructure and the pass-through. Do **not** remove the `selectedId` *variable* in App.jsx (1011-1012) — it's used by the properties panel (1628, 1658).

**`FONTS` is exported from Label.jsx but no module imports it** (nit, `src/Label.jsx:956`, 2/2) — still used internally (lines 14, 144, 172), so not dead code — only the export entry is unused. **Fix:** drop `FONTS` from the export list. Non-breaking.

## React Anti-Pattern

**Component `K` defined inside HelpModal render body** (nit, `src/App.jsx:872`, 2/2) — `const K = ({ children }) => <kbd>{children}</kbd>;` is re-created each render. Impact theoretical (static, mounts only while dialog open). **Fix:** hoist to module scope alongside Row/Seg (closes over nothing — verbatim move).
